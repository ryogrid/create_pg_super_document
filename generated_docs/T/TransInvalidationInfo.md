# TransInvalidationInfo

## Location
src/backend/utils/cache/inval.c: 220 - 236

## Overview
TransInvalidationInfo is a data structure that manages cache invalidation state for PostgreSQL transactions and subtransactions, organizing invalidation messages by transaction nesting level and command boundaries.

## Definition


## Detailed Description
TransInvalidationInfo forms the core of PostgreSQL's transaction-aware cache invalidation system. It maintains a stack-like structure where each transaction and subtransaction level has its own instance, linked through the parent pointer. This design enables proper handling of nested transactions and allows for correct rollback behavior when subtransactions abort.

The structure separates invalidation messages into two categories: those generated by the current command (CurrentCmdInvalidMsgs) and those from previous commands within the same transaction (PriorCmdInvalidMsgs). This separation is crucial because current command messages haven't been reflected to caches yet, while prior command messages have been reflected locally and need different handling during commit/abort.

When a subtransaction commits, its invalidation messages are appended to the parent transaction's groups. When a subtransaction aborts, its messages are simply discarded. This mechanism ensures that cache invalidations are properly propagated or rolled back according to transaction semantics.

- The RelcacheInitFileInval flag is transaction-level rather than command-level since only transaction commit triggers action
