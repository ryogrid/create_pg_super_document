## Overview
PrintControlValues displays the current or guessed pg_control file values in a human-readable format for diagnostic and verification purposes.

## Definition


## Detailed Description
This function provides a comprehensive display of the PostgreSQL control file contents, showing critical database configuration and state information in a formatted, user-friendly manner. The output includes both static configuration parameters (like block sizes and alignment settings) and dynamic state information (like transaction IDs and checkpoint data).

The function serves multiple purposes:
1. **Diagnostic Output**: Allows administrators to verify current database configuration and state
2. **Verification**: Shows the values that pg_resetwal will use, whether read from an existing control file or guessed
3. **Documentation**: Provides a complete snapshot of critical database parameters
4. **Troubleshooting**: Helps identify configuration mismatches or corruption issues

The display is carefully curated to show only fields that will not be reset by the RewriteControlFile() function, making it useful for understanding what values will persist after pg_resetwal completes its operation.

- : Boolean flag indicating whether the displayed values were read from a valid control file (false) or generated by GuessControlValues() (true). This affects the header message displayed to the user.

## Notes and Other Information
- This is a static function, accessible only within pg_resetwal.c
- Uses internationalization macros (_()) to support localized output messages
- Displays transaction IDs in epoch:xid format for better readability
- Includes both critical operational values (NextXID, TimeLineID) and configuration constants (block sizes, alignment)
- Omits the floatFormat field as it's not particularly useful for users
- Shows hardcoded "64-bit integers" for date/time storage as this is no longer configurable
- The boolean values (like full_page_writes and float8ByVal) are displayed as human-readable "on/off" or "by value/by reference" strings
- Provides essential information for database administrators to understand the database's current state and configuration before and after running pg_resetwal
- The output format is designed to be both machine-parseable and human-readable for administrative scripts and manual inspection
