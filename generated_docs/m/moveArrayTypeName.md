# moveArrayTypeName

## Location
[src/backend/catalog/pg_type.c:905-949](https://github.com/postgres/postgres/tree/92268b35d04c2de416279f187d12f264afa22614/src/backend/catalog/pg_type.c#L905-L949)

## Overview
moveArrayTypeName handles the renaming of existing array types to avoid naming conflicts when creating new PostgreSQL types, specifically designed to resolve situations where a user wants to create type "foo" followed by type "_foo".

## Definition
bool moveArrayTypeName(Oid typeOid, const char *typeName, Oid typeNamespace)

## Detailed Description
This function attempts to reassign an array type name that the user wants to use for a new type. When PostgreSQL discovers that a given type name already exists with a specific OID, moveArrayTypeName checks if it is an autogenerated array type and, if so, changes the existing array type's name to avoid conflicts.

The function is crucial for PostgreSQL's type system as it allows users to create types with predictable naming patterns without worrying about conflicts with automatically generated array type names. It must be called before makeArrayTypeName to determine the new type's own array type name, ensuring the latter doesn't pick the same conflicting name.

The function implements a safety mechanism where it only renames autogenerated array types, preserving user-defined types. It also handles shell types (incomplete type definitions) by returning true without renaming, since shell types can be expected to allow TypeCreate to succeed.

## Parameters / Member Variables
- `typeOid`: The OID of the existing type that conflicts with the desired name
- `typeName`: The name that the user wants to use for their new type
- `typeNamespace`: The namespace (schema) where the type resides

## Notes and Other Information
The function returns true if it successfully moved the type or if the given type is a shell type, and false if the type cannot be moved (e.g., it's not an autogenerated array type). Race conditions can occur if multiple backends try to create similarly-named types concurrently, but any changes made by this function will be rolled back if the subsequent type creation fails due to naming conflicts. The function uses CommandCounterIncrement to ensure that subsequent calls to makeArrayTypeName see the changes made by the rename operation.
