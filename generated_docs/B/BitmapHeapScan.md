# BitmapHeapScan

## Location
[src/include/nodes/plannodes.h:538-542](https://github.com/postgres/postgres/tree/92268b35d04c2de416279f187d12f264afa22614/src/include/nodes/plannodes.h#L538-L542)

## Overview
BitmapHeapScan is a PostgreSQL plan node that scans heap pages using a bitmap generated by bitmap index scans, providing efficient access to scattered tuples.

## Definition
```c
typedef struct BitmapHeapScan
{
    Scan        scan;
    List       *bitmapqualorig; /* index quals, in standard expr form */
} BitmapHeapScan;
```

## Detailed Description
BitmapHeapScan is the counterpart to BitmapIndexScan in PostgreSQL's bitmap scan mechanism. While BitmapIndexScan generates a bitmap of potential tuple locations, BitmapHeapScan uses that bitmap to efficiently access the actual heap pages and tuples. This two-phase approach is particularly beneficial when index conditions would result in scattered heap page accesses.

The node maintains a copy of the qualification conditions from the input index scans because there are various cases where recheck of the quals is necessary. For example, when the bitmap is lossy (meaning it indicates pages that might contain matching rows rather than exact tuple positions), the heap scan must re-evaluate the index conditions against each tuple to determine actual matches.

## Parameters / Member Variables
- `scan`: Base Scan structure containing common scan node fields including relation information, target list, and scan qualifications
- `bitmapqualorig`: List containing the original index qualification expressions in standard expression form, used for rechecking conditions when necessary

## Notes and Other Information
- [BitmapHeapScan](BitmapHeapScan.md) works in conjunction with BitmapIndexScan and potentially BitmapAnd/BitmapOr nodes to implement efficient multi-index access patterns
- The bitmap can be exact (indicating specific tuple locations) or lossy (indicating pages that may contain matches), requiring different handling strategies
- This scan type is most effective when the bitmap indicates a moderate number of scattered pages, avoiding the overhead of random I/O that would occur with nested loop joins
- The bitmapqualorig field is essential for maintaining query correctness when bitmap information is incomplete or approximate
- Supports both sequential and parallel execution models depending on the query plan and system configuration
