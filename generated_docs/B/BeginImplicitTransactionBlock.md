# BeginImplicitTransactionBlock\n\n## Overview\nBeginImplicitTransactionBlock starts an implicit transaction block by transitioning from STARTED state to IMPLICIT_INPROGRESS state when no explicit transaction is active.\n\n## Definition\nvoid BeginImplicitTransactionBlock(void)\n\n## Detailed Description\nBeginImplicitTransactionBlock creates an implicit transaction block when the system is in STARTED state (no active transaction block). Unlike BeginTransactionBlock, this function is called directly from the main loop in postgres.c rather than within a Portal context. It performs a simple state transition without requiring ceremonial commit/start transaction commands. The function is designed for caller convenience and accepts calls in any transaction state, only taking action when in STARTED state. Implicit transaction blocks are used internally by PostgreSQL to group operations that should be atomic but aren't explicitly wrapped in BEGIN/COMMIT blocks.\n\n## Parameters / Member Variables\n- None (void function)\n\n## Dependencies\n- Functions called/Symbols referenced:\n  - CurrentTransactionState (global variable)\n  - TBLOCK_STARTED (state constant)\n  - TBLOCK_IMPLICIT_INPROGRESS (state constant)\n- Called from (representative examples):\n  - exec_simple_query\n\n## Notes and Other Information\n- Only transitions state when currently in TBLOCK_STARTED state\n- Accepts calls in any transaction state for caller convenience\n- Called directly from main loop rather than Portal context\n- Does not require CommitTransactionCommand/StartTransactionCommand ceremony\n- Creates implicit transaction blocks for internal atomicity requirements\n- No-op if already in a transaction block or other non-STARTED state
