# ForeignScan

## Overview
ForeignScan is a plan node that represents scanning data from foreign tables through PostgreSQL's Foreign Data Wrapper (FDW) interface, supporting both simple scans and direct modifications.

## Definition
```c
typedef struct ForeignScan
{
    Scan        scan;
    CmdType     operation;          /* SELECT/INSERT/UPDATE/DELETE */
    Index       resultRelation;     /* direct modification target's RT index */
    Oid         checkAsUser;        /* user to perform the scan as; 0 means to
                                     * check as current user */
    Oid         fs_server;          /* OID of foreign server */
    List       *fdw_exprs;          /* expressions that FDW may evaluate */
    List       *fdw_private;        /* private data for FDW */
    List       *fdw_scan_tlist;     /* optional tlist describing scan tuple */
    List       *fdw_recheck_quals;  /* original quals not in scan.plan.qual */
    Bitmapset  *fs_relids;          /* base+OJ RTIs generated by this scan */
    Bitmapset  *fs_base_relids;     /* base RTIs generated by this scan */
    bool        fsSystemCol;        /* true if any "system column" is needed */
} ForeignScan;
```

## Detailed Description
ForeignScan is the plan node used to access data from foreign tables via the Foreign Data Wrapper (FDW) API. It extends the base Scan structure with FDW-specific functionality and can represent both simple foreign table scans and direct modifications (INSERT/UPDATE/DELETE) performed remotely. The structure allows FDW implementations to store private data, specify expressions for remote evaluation, and handle complex scenarios like foreign joins. The node supports advanced features including parallel execution, EvalPlanQual rechecking, and security context switching for different users. When used for foreign joins, the scan.scanrelid is zero and fs_relids identifies the involved relations.

## Parameters / Member Variables
- `scan`: Base Scan structure containing common scan fields (Plan plan, Index scanrelid)
- `operation`: CmdType indicating the operation type (SELECT, INSERT, UPDATE, DELETE)
- `resultRelation`: Index of the target relation in the range table for direct modifications
- `checkAsUser`: OID of the user to perform security checks as (0 means current user)
- `fs_server`: OID of the foreign server being accessed
- `fdw_exprs`: List of expressions that the FDW may evaluate remotely
- `fdw_private`: List of FDW-specific private data (opaque to core PostgreSQL)
- `fdw_scan_tlist`: Optional target list describing the scan tuple format
- `fdw_recheck_quals`: Qualification expressions that need local rechecking for EvalPlanQual
- `fs_relids`: Bitmapset of all relation IDs involved (including outer joins)
- `fs_base_relids`: Bitmapset of base relation IDs only (excluding outer joins)
- `fsSystemCol`: Boolean indicating if any system columns are needed

## Notes and Other Information
- Supports both simple foreign table scans and complex foreign joins
- Can perform direct modifications (UPDATE/DELETE) remotely when FDW supports it
- The fdw_exprs and fdw_private fields are under complete FDW control
- fdw_scan_tlist is required for foreign joins since no system rowtype exists
- Supports parallel execution through FDW-specific coordination mechanisms
- EvalPlanQual support through fdw_recheck_quals for consistent reads
- Security context can be switched using checkAsUser field
- When operation is not CMD_SELECT, the node performs direct remote modifications
- fs_relids vs fs_base_relids distinction important for join planning and execution
