# DecodeMultiInsert

## Location
src/backend/replication/logical/decode.c: 1124 - 1229

## Overview
DecodeMultiInsert processes XLOG_HEAP2_MULTI_INSERT WAL records during logical replication, converting a single multi-insert operation into multiple individual insert change records in the reorder buffer.

## Definition
```c
static void DecodeMultiInsert(LogicalDecodingContext *ctx, XLogRecordBuffer *buf)
```

## Detailed Description
DecodeMultiInsert handles the decoding of multi-insert operations (bulk inserts) from the write-ahead log during logical replication. When PostgreSQL performs bulk inserts (like COPY or INSERT with multiple VALUES), it can generate XLOG_HEAP2_MULTI_INSERT records that contain multiple tuples in a single WAL record for efficiency.

The function extracts each individual tuple from the multi-insert record and creates separate reorder buffer changes for each one. This allows logical replication output plugins to process each inserted tuple individually, maintaining the logical semantics expected by downstream systems.

Key processing steps:
1. Validates the record contains new tuples (excludes catalog/temp table operations)
2. Filters by database and replication origin
3. Iterates through all tuples in the multi-insert record
4. Reconstructs each HeapTuple from the compact WAL representation
5. Handles toast reassembly state management for the last tuple in a sequence
6. Queues individual insert changes in the reorder buffer

## Parameters / Member Variables
- `ctx`: LogicalDecodingContext containing the decoding session state, replication slot, and reorder buffer
- `buf`: XLogRecordBuffer containing the multi-insert WAL record and its metadata

## Notes and Other Information
- This function always expects full tuples in multi-insert records (not just tuple deltas)
- Handles toast reassembly state correctly by only clearing it after the last tuple in the final multi-insert record
- Uses SHORTALIGN for proper memory alignment when reading xl_multi_insert_tuple headers
- The function reconstructs complete HeapTuple structures from the compact WAL representation
- Multi-insert records are generated by operations like COPY and multi-value INSERT statements
- Each tuple gets its own individual change record despite originating from a single multi-insert operation
- Catalog table multi-inserts are filtered out as they don't contain new tuples relevant for logical replication
