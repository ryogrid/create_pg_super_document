## Overview
Queues transactional logical messages for later processing upon commit or processes non-transactional messages immediately during logical replication decoding.

## Detailed Description
This function handles logical messages generated by pg_logical_emit_message() during logical replication. It supports both transactional and non-transactional messages with different processing paths. Transactional messages are queued as changes within transactions and processed during commit, ensuring they follow transaction boundaries and ordering. Non-transactional messages are processed immediately using the provided snapshot, bypassing transaction queuing and allowing real-time delivery. The function manages memory allocation, snapshot setup, and proper error handling for both message types.

## Notes and Other Information
- Transactional messages are queued as REORDER_BUFFER_CHANGE_MESSAGE changes and processed during transaction commit
- Non-transactional messages bypass transaction queuing and are processed immediately with the provided snapshot
- Transactional messages must have a valid transaction ID and cannot have an associated snapshot
- Non-transactional messages require a valid snapshot but may have InvalidTransactionId
- Memory for transactional messages is allocated in the ReorderBuffer's memory context
- Uses PG_TRY/PG_CATCH blocks to ensure proper snapshot cleanup on errors
- The rb->message callback is responsible for the actual message processing/delivery
- Message data is copied to ensure it remains valid for later processing in transactional cases
- Both prefix and message content are preserved exactly as provided in the WAL record
