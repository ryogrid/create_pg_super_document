# RmgrIds

## Location
[src/include/access/rmgr.h:29-30](https://github.com/postgres/postgres/tree/92268b35d04c2de416279f187d12f264afa22614/src/include/access/rmgr.h#L29-L30)

## Overview
An enumeration that defines all resource manager identifiers used in PostgreSQL's Write-Ahead Logging (WAL) system.

## Definition
```c
typedef enum RmgrIds
{
#include "access/rmgrlist.h"
	RM_NEXT_ID
} RmgrIds;
```

## Detailed Description
RmgrIds is an enumeration type that defines unique identifiers for all resource managers in PostgreSQL. Resource managers are components responsible for handling specific types of WAL records during normal operation and recovery. The enum values are generated by including rmgrlist.h, which uses the PG_RMGR macro to define each resource manager entry.

The enumeration includes all built-in PostgreSQL resource managers such as:
- RM_XLOG_ID: WAL management operations
- RM_XACT_ID: Transaction management
- RM_HEAP_ID: Heap table operations  
- RM_BTREE_ID: B-tree index operations
- RM_HASH_ID: Hash index operations
- RM_GIN_ID: GIN index operations
- RM_GIST_ID: GiST index operations
- RM_SPGIST_ID: SP-GiST index operations
- RM_BRIN_ID: BRIN index operations
- And many others for different PostgreSQL subsystems

The RM_NEXT_ID sentinel value marks the end of built-in resource managers and is used to calculate RM_MAX_BUILTIN_ID.

## Parameters / Member Variables
The enum contains the following categories of resource manager IDs:
- **Core WAL managers**: RM_XLOG_ID, RM_XACT_ID for fundamental WAL and transaction operations
- **Storage managers**: RM_SMGR_ID, RM_DBASE_ID, RM_TBLSPC_ID for storage and database management
- **Table access managers**: RM_HEAP_ID, RM_HEAP2_ID for heap table operations
- **Index managers**: RM_BTREE_ID, RM_HASH_ID, RM_GIN_ID, RM_GIST_ID, RM_SPGIST_ID, RM_BRIN_ID for various index types
- **Utility managers**: RM_SEQ_ID, RM_MULTIXACT_ID, RM_RELMAP_ID for sequences, multixacts, and relation mapping
- **Replication managers**: RM_STANDBY_ID, RM_REPLORIGIN_ID, RM_LOGICALMSG_ID for standby and replication operations
- **Specialized managers**: RM_CLOG_ID, RM_COMMIT_TS_ID, RM_GENERIC_ID for commit logging, commit timestamps, and generic operations
- **Sentinel**: RM_NEXT_ID to mark the boundary between built-in and custom resource managers

## Notes and Other Information
- The numerical values of enum entries are critical as they are stored in WAL records on disk
- New resource managers must be added at the end of rmgrlist.h to avoid changing existing IDs
- Changes to this enum may require bumping XLOG_PAGE_MAGIC
- The order in rmgrlist.h determines the numerical values (0, 1, 2, etc.)
- Custom resource managers use IDs starting from RM_MIN_CUSTOM_ID (128)
- Used with RmgrIdIsBuiltin() and RmgrIdIsCustom() functions to validate and categorize resource manager IDs
- This design allows extensions to register their own resource managers without conflicting with built-in ones
