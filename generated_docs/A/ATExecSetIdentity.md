# ATExecSetIdentity

## Location
src/backend/commands/tablecmds.c: 8129 - 8245

## Overview
ATExecSetIdentity implements the ALTER TABLE ALTER COLUMN SET { GENERATED or sequence options } command, allowing modification of identity column properties in PostgreSQL relations.

## Definition
```c
static ObjectAddress ATExecSetIdentity(Relation rel, const char *colName, Node *def, LOCKMODE lockmode, bool recurse, bool recursing)
```

## Detailed Description
This function modifies the properties of an existing identity column, primarily changing between GENERATED ALWAYS and GENERATED BY DEFAULT modes. It processes a list of options and validates that the target column is already an identity column before making any changes.

The function performs comprehensive validation:
- Ensures the column exists and is not a system column
- Verifies the column is already an identity column
- Validates partitioning constraints (changes cannot be made to only the partitioned table without RECURSE, and cannot be made directly to partitions)
- Parses the provided options list to extract the "generated" element

The function supports changing the identity generation mode (ALWAYS vs BY DEFAULT) and runs all validation checks even when no changes are made, as subsequent ALTER SEQUENCE commands may rely on the validation. For partitioned tables, it recursively applies changes to all child partitions when the recurse flag is set.

## Parameters / Member Variables
- `rel`: The relation containing the identity column to modify
- `colName`: Name of the identity column to modify
- `def`: List node containing the identity options to set
- `lockmode`: Lock mode to use when accessing child relations
- `recurse`: Whether to apply changes to partitioned table children
- `recursing`: Internal flag indicating this is a recursive call to a partition

## Notes and Other Information
- This is a static function within tablecmds.c, part of the ALTER TABLE infrastructure
- Runs validation checks even when no actual changes are made, supporting subsequent ALTER SEQUENCE operations
- Currently only supports the "generated" option, reporting errors for unrecognized options
- The identity property changes are not inherited through regular table inheritance, only through partitioning
- Returns InvalidObjectAddress when no actual changes are made (when generatedEl is NULL)
- Supports both GENERATED ALWAYS (typically value 1) and GENERATED BY DEFAULT (typically value 0) modes
- Uses recursive calls to propagate identity property changes to all partitions
- The function distinguishes between partitioned tables (where recursion is required) and regular inheritance (where identity is not inherited)
