# CustomScan

## Location
[src/include/nodes/plannodes.h:739-756](https://github.com/postgres/postgres/tree/92268b35d04c2de416279f187d12f264afa22614/src/include/nodes/plannodes.h#L739-L756)

## Overview
CustomScan is a plan node that allows third-party extensions to implement custom scanning logic within PostgreSQL's execution framework through the extensible node interface.

## Definition
```c
typedef struct CustomScan
{
    Scan        scan;
    uint32      flags;              /* mask of CUSTOMPATH_* flags, see
                                     * nodes/extensible.h */
    List       *custom_plans;       /* list of Plan nodes, if any */
    List       *custom_exprs;       /* expressions that custom code may evaluate */
    List       *custom_private;     /* private data for custom code */
    List       *custom_scan_tlist;  /* optional tlist describing scan tuple */
    Bitmapset  *custom_relids;      /* RTIs generated by this scan */

    /*
     * NOTE: The method field of CustomScan is required to be a pointer to a
     * static table of callback functions.  So we don't copy the table itself,
     * just reference the original one.
     */
    const struct CustomScanMethods *methods;
} CustomScan;
```

## Detailed Description
CustomScan provides an extensibility mechanism for PostgreSQL, allowing external extensions to implement custom scanning and processing logic that integrates seamlessly with the query executor. This node type supports various advanced capabilities through the flags field, including backward scanning, mark/restore functionality, and projection capabilities. Custom scan providers can define complex execution trees with child plans, maintain private state data, and specify custom expressions for evaluation. The node uses a callback-based architecture where the methods field points to a static table of function pointers that implement the custom scanning behavior. This design allows extensions to leverage PostgreSQL's sophisticated cost-based optimization and execution framework while providing their own specialized data access patterns.

## Parameters / Member Variables
- `scan`: Base Scan structure containing common scan fields (Plan plan, Index scanrelid)
- `flags`: Bitmask of CUSTOMPATH_* capability flags (SUPPORT_BACKWARD_SCAN, SUPPORT_MARK_RESTORE, SUPPORT_PROJECTION)
- `custom_plans`: List of child Plan nodes for complex custom execution trees
- `custom_exprs`: List of expressions that the custom scan code may evaluate during execution
- `custom_private`: List of extension-specific private data in nodeToString-compatible format
- `custom_scan_tlist`: Optional target list describing the format of scan tuples produced
- `custom_relids`: Bitmapset of relation table entry (RTI) IDs that this scan accesses
- `methods`: Pointer to static CustomScanMethods structure containing callback functions

## Notes and Other Information
- Part of PostgreSQL's extensible node framework for third-party extensions
- Supports advanced capabilities: backward scanning, mark/restore, and projection
- The methods field must point to static callback table (not copied, just referenced)
- Custom scan providers must handle all aspects of their execution through callbacks
- Flags control which optional executor features the custom scan supports
- Can implement both simple scans and complex join-like operations
- Integration with cost-based optimization through standard Path/Plan framework
- Private data must be in nodeToString-compatible format for debugging support
- Used by extensions like pg_pathman, postgres_fdw (for some cases), and custom indexing solutions
- Supports parallel execution through extension-specific coordination mechanisms
