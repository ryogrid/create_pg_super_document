# CreatePartitionPruneState

## Location
src/backend/executor/execPartition.c: 1867 - 2096

## Overview
Builds the data structure required for calling ExecFindMatchingSubPlans by creating a comprehensive PartitionPruneState with hierarchical pruning data structures.

## Definition
```c
static PartitionPruneState *CreatePartitionPruneState(PlanState *planstate, PartitionPruneInfo *pruneinfo)
```

## Detailed Description
This function constructs a complex two-level data structure (PartitionPruneState) that manages partition pruning for potentially multiple partitioned table hierarchies. It handles the case where UNION ALL queries contain multiple partitioned tables as children by creating separate PartitionPruningData structures for each hierarchy. The function manages the mapping between partition indexes and subplan indexes, handles partition descriptor changes between plan time and execution time, and initializes pruning contexts for both initial and execution-time pruning. It also creates a dedicated memory context for pruning operations to prevent memory leaks.

## Parameters / Member Variables
- `planstate`: The parent plan node's execution state (typically Append or MergeAppend)
- `pruneinfo`: PartitionPruneInfo structure generated by the planner containing pruning steps and hierarchy information

## Notes and Other Information
- Static function only accessible within execPartition.c
- Creates a two-level hierarchy: PartitionPruneState contains PartitionPruningData arrays, each containing PartitionedRelPruningData structures
- Handles dynamic partition changes by comparing current partition descriptors with those from plan time
- Creates separate memory context ("Partition Prune") to avoid memory leaks from comparison functions
- Supports both initial pruning (at startup) and execution-time pruning (per scan)
- Accumulates PARAM_EXEC parameter IDs that affect partitioning decisions
- Skips execution-time pruning during EXPLAIN (GENERIC_PLAN) when parameter values may be missing
- Maps partition OIDs between plan-time and execution-time, handling cases where partitions may have been added or removed
