PostgreSQL system catalogs (pg_catalog schema). Total: 63 catalog tables.

Discovery method:
  for f in src/include/catalog/pg_*.h; do grep -E "^CATALOG\(...\," $f; done

Flag legend:
  shared    : BKI_SHARED_RELATION  -- single physical relation visible from every database
              (lives in pg_global tablespace)
  nailed    : BKI_BOOTSTRAP        -- formrdesc-bootstrapped relcache entry; the relcache
              cannot be initialized without these existing in C-side metadata
  mapped    : entry in pg_filenode.map (the relfilenode is NOT recorded in pg_class because
              we cannot safely update pg_class for these catalogs)
              By inspection of relmapper.c MAX_MAPPINGS=64 and IsSharedRelation() in catalog.c,
              the mapped catalogs are: the 4 nailed local (pg_class, pg_attribute, pg_proc,
              pg_type) plus all 11 shared ones, plus their indexes and toast tables.
  .dat      : has src/include/catalog/<name>.dat boot data
  .c        : has src/backend/catalog/<name>.c C-side helper

Format per row:
  name  | OID  | flags                            | .dat | .c   | brief purpose
        | (.h is always src/include/catalog/<name>.h; key indexes from indexing.h within <name>.h)

Notes
================================================================================

* Total = 11 shared + 4 nailed + 48 local = 63 catalogs (compare against the
  request's >= 60).

* The cluster control file pg_control (catalog/pg_control.h) is NOT a heap
  relation; it is a single binary file pg_control written atomically. It is
  declared here so that its format is documented but it is not part of pg_catalog.

* CATALOG_VERSION_NO (catversion.h) is bumped any time a catalog header changes
  or a system index is added/removed. ReadControlFile rejects a cluster whose
  catalog_version_no does not match.

* Bootstrap data:
  - .dat files are read by genbki.pl and emitted into postgres.bki.
  - postgres --boot consumes postgres.bki via bootparse.y / bootscanner.l
    and inserts the rows directly.
  - The 4 nailed catalogs (pg_class, pg_attribute, pg_proc, pg_type) plus
    the shared variants get formrdesc()-built relcache entries during the
    Phase-2/Phase-3 relcache initialization.

* Per-catalog C-side helper files:
  - heap.c, index.c, indexing.c, dependency.c, namespace.c, storage.c,
    toasting.c, aclchk.c, objectaccess.c, objectaddress.c, partition.c
    are general infrastructure (counted separately).
  - pg_aggregate.c, pg_attrdef.c, pg_cast.c, pg_class.c, pg_collation.c,
    pg_constraint.c, pg_conversion.c, pg_db_role_setting.c, pg_depend.c,
    pg_enum.c, pg_inherits.c, pg_largeobject.c, pg_namespace.c, pg_operator.c,
    pg_parameter_acl.c, pg_proc.c, pg_publication.c, pg_range.c, pg_shdepend.c,
    pg_subscription.c, pg_type.c -- these are catalog-specific helpers
    (e.g. CreateTypeEntry, CreateConstraintEntry, get_role_oid).

* Shared and nailed catalogs cannot be tracked through pg_class.relfilenode
  because:
  - For shared relations there is no single pg_class to update across all
    databases; the same physical file is visible from every database, but
    each database has its own pg_class.
  - For nailed relations the relcache must be operational before pg_class
    itself can be opened, so we cannot rely on a pg_class lookup to find
    pg_class's own filenode.
  Hence relmapper.c keeps a small file (pg_filenode.map -- under PGDATA/global
  for shared, under PGDATA/base/<dbid> for local) that maps catalog Oid ->
  RelFileNumber. The mapping is updated atomically and replicated via
  XLOG_RELMAP_UPDATE.
