    payload: CheckPoint (pg_control.h:35)

    nextMulti, nextMultiOffset, oldestXid, oldestMulti, oldestCommitTsXid,
    newestCommitTsXid, redo, fullPageWrites). Also written into pg_control.
    Ref: src/include/catalog/pg_control.h:68

 2. XLOG_CHECKPOINT_ONLINE  (info 0x10)
    payload: CheckPoint
    Same as SHUTDOWN but with oldestActiveXid set, used for replica startup.
    Ref: src/include/catalog/pg_control.h:69

 3. XLOG_NEXTOID  (info 0x30)
    payload: Oid (next OID checkpoint)
    Makes durable: the OID counter advance. Emitted by GetNewObjectId every
    VAR_OID_PREFETCH OIDs so a crash never reuses an OID.
    Ref: src/include/catalog/pg_control.h:71  (emit site: src/backend/access/transam/varsup.c)

 4. XLOG_FPI  (info 0xB0)
    payload: full-page image (no extra data; the registered buffer carries the page)
    Makes durable: a full-page image of a non-WAL-logged change, written to ensure
    a torn-page-safe initial image. Used by VACUUM page-prune in some cases.
    Ref: src/include/catalog/pg_control.h:79

 5. XLOG_FPI_FOR_HINT  (info 0xA0)
    payload: full-page image
    Makes durable: a full-page image emitted as a side-effect of MarkBufferDirtyHint
    when checksums or wal_log_hints are enabled. Required for hint-bit-only changes
    (HEAP_XMIN_COMMITTED etc.) so a torn page does not corrupt the bits.
    Ref: src/include/catalog/pg_control.h:78

 6. XLOG_CHECKPOINT_REDO  (info 0xE0)
    payload: (small marker)
    Makes durable: the precise WAL location where redo will start; inserted at the
    moment the redo pointer is computed in CreateCheckPoint.
    Ref: src/include/catalog/pg_control.h:82

================================================================================

  during xact_redo_commit, and broadcasts cache invalidations.
* RM_XACT_ID's XLOG_XACT_ABORT implicitly updates CLOG via TransactionIdAbortTree.
* RM_HEAP_ID heap mutations implicitly clear the VM ALL_VISIBLE bit during their
  redo (visibilitymap_clear; not WAL-logged separately).
