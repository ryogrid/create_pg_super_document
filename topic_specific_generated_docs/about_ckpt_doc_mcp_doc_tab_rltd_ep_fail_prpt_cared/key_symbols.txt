Key Architectural Components:
============================

CHECKPOINT CONTROL (Entry Points):
- CheckpointerMain: Main checkpointer process loop with scheduling logic
- RequestCheckpoint: Backend interface for checkpoint requests
- CreateCheckPoint: Core checkpoint orchestration

BUFFER MANAGEMENT (I/O Intensive):
- BufferSync: Checkpoint buffer synchronization with tablespace balancing
- SyncOneBuffer: Individual buffer sync used by both checkpoint and bgwriter
- FlushBuffer: Low-level buffer flushing enforcing WAL-before-data rule

WAL COORDINATION (Consistency Critical):
- XLogFlush: WAL flushing ensuring write-ahead logging consistency
- XLogWrite: Physical WAL writes with segment management
- XLogInsert: WAL record insertion with LSN assignment

PERFORMANCE CONTROL (I/O Throttling):
- CheckpointWriteDelay: Adaptive I/O throttling spreading checkpoint load
- BgBufferSync: Background cleaning reducing checkpoint I/O spikes

RECOVERY COORDINATION (Crash Safety):
- UpdateControlFile: Atomic control file updates for recovery consistency
- CreateRestartPoint: Standby server checkpoint handling during recovery

Critical Flow Patterns:
======================

1. Checkpoint Initiation → Buffer Flushing → WAL Coordination → Control File Update
2. Background Writer → Proactive Buffer Cleaning → Reduced Checkpoint Load
3. WAL-Before-Data → XLogFlush → Buffer Write → Storage Consistency
4. Tablespace Load Balancing → I/O Spreading → Performance Optimization
5. Recovery Point Management → Standby Coordination → High Availability Support

These symbols form the backbone of PostgreSQL's checkpointing architecture, ensuring
data consistency, crash recovery capability, and optimal I/O performance across
various workload patterns.
