Mutual-exclusion enforcement: validateRecoveryParameters
(xlogrecovery.c:1109) plus per-GUC check hooks (each refuses to be set
if another recovery_target_* is already armed via the 'extra' pointer

8. recovery_target_action
   GUC table:           guc_tables.c:4924
   Type:                enum (PGC_POSTMASTER)
   Default:             RECOVERY_TARGET_ACTION_PAUSE
   Allowed values:      pause, promote, shutdown
                        (recovery_target_action_options[])
   Backing store:       recoveryTargetAction (RecoveryTargetAction enum
                        in xlog_internal.h:322)
   Parser/Assign:       NULL/NULL
   Behavior:            after stop predicate fires:
                        PAUSE -> SetRecoveryPause(true); user must
                                pg_wal_replay_resume / pg_promote
                        PROMOTE -> SignalPromotion; same path as
                                'promote' file
                        SHUTDOWN -> proc_exit(0) inside StartupXLOG,
                                postmaster sees clean exit, cluster goes
                                to DB_SHUTDOWNED_IN_RECOVERY and stops.
                        Special: validateRecoveryParameters demotes
                        PAUSE to SHUTDOWN if hot_standby is off.

9. recovery_min_apply_delay
   GUC table:           guc_tables.c:2172
   Type:                int (ms; PGC_SIGHUP, REPLICATION_STANDBY)
   Default:             0  (range 0..INT_MAX)
   Backing store:       recovery_min_apply_delay
   Parser/Assign:       NULL/NULL
   Compare in record:   record's xact_time on XACT_COMMIT / COMMIT_PREPARED
   Stop predicate:      none (it's a delay, not a stop). Implemented in
                        recoveryApplyDelay (xlogrecovery.c:2510): waits
                        until xact_time + recovery_min_apply_delay <= now
                        before letting ApplyWalRecord process the commit.
                        SIGHUP and recoveryPause checks inside the wait.

10. restore_command  (recovery-related companion, not a recovery_target)
    Listed because it co-validates with recovery_target_* in
    validateRecoveryParameters: archive recovery without standby mode
    REQUIRES restore_command to be set.

11. recovery_end_command  (companion)
    Run once just after StartupXLOG transitions out of recovery
    (post-promotion). Typical use: tell an operator system that the
    cluster has been promoted.

12. archive_cleanup_command  (companion)
    Run from CreateRestartPoint after pg_wal recycling, used to clean
    up the WAL archive of segments older than the new restartpoint
    (`%r` substitution).
