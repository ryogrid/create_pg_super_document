Backend-side common path:
  signal arrival -> HandleRecoveryConflictInterrupt

  next CFI -> ProcessRecoveryConflictInterrupts (postgres.c:3232)

5. PROCSIG_RECOVERY_CONFLICT_LOGICALSLOT
   Enum:                procsignal.h:46  (named PROCSIG_RECOVERY_CONFLICT_LOGICALSLOT
                        - the bookkeeping mirror of the docs' "logical
                          slot" conflict label)
   Conflict type:       logical replication slot's catalog_xmin /
                        restart_lsn would invalidate slots; when standby
                        replays records that violate the slot's needs.
   Trigger redo paths:  any record that advances the standby's
                        latestRemovedXid past the slot's catalog_xmin
                        OR drops a database the slot references.
   Resolver (standby):  inline in slot.c:
                        ReplicationSlotsDropDBSlots /
                        InvalidatePossiblyObsoleteSlot
                        (the conflict is delivered to the logical-decoding
                         consumer which holds the slot, not to the slot's
                         own LSN advance path)
   Grace period GUC:    max_slot_wal_keep_size and the
                        invalidate-on-conflict policy
                        (max_standby_archive_delay /
                         max_standby_streaming_delay also apply through
                         the consumer's wait paths)
   Victim policy:       backend that owns the active replication slot.
   Backend handler:     ereport(ERROR) for logical decoding consumer;
                        slot becomes invalidated.

6. PROCSIG_RECOVERY_CONFLICT_BUFFERPIN
   Enum:                procsignal.h:47
   Conflict type:       startup process needs cleanup access to a buffer
                        another backend has pinned (e.g. for VM bit or
                        page reuse).
   Trigger redo path:   any redo callback that calls
                        LockBufferForCleanup; in practice
                        heap2_redo XLOG_HEAP2_VISIBLE,
                        btree_redo / hash_redo VACUUM-class records.
   Resolver (standby):  ResolveRecoveryConflictWithBufferPin
                        src/backend/storage/ipc/standby.c:792
                        - sets STANDBY_TIMEOUT timer; on expiry, signals
                        every pinned buffer's holder
   Grace period GUC:    max_standby_archive_delay /
                        max_standby_streaming_delay (used as
                        STANDBY_TIMEOUT seed)
   Victim policy:       backends holding pins on the buffer
                        (SendRecoveryConflictWithBufferPin signals all
                         active backends; only the actual holders are
                         affected because non-holders ignore via
                         RecoveryConflictPendingReasons[])
   Backend handler:     ProcessRecoveryConflictInterrupt special-case:
                        if blocking startup AND idle, just release the
                        pin (no cancel); else ereport(ERROR).

7. PROCSIG_RECOVERY_CONFLICT_STARTUP_DEADLOCK
   Enum:                procsignal.h:48
   Conflict type:       circular wait between startup process and a
                        backend (the backend is waiting on a lock the
                        startup process holds while pinning the buffer
                        the startup process needs).
   Trigger redo path:   detected by CheckRecoveryConflictDeadlock
                        (standby.c:921) when STANDBY_DEADLOCK_TIMEOUT
                        fires inside ResolveRecoveryConflictWithBufferPin
   Resolver (standby):  CheckRecoveryConflictDeadlock signals
                        PROCSIG_RECOVERY_CONFLICT_STARTUP_DEADLOCK to the
                        candidate; effect: backend is canceled
                        unconditionally.
   Grace period GUC:    deadlock_timeout (and the standard
                        max_standby_*_delay still applies for the
                        outer wait)
   Victim policy:       the backend chosen by the deadlock check.
   Backend handler:     ereport(FATAL) - terminates the connection.
                        Required because ERROR is insufficient: the
                        deadlock cycle includes a non-transactional
                        buffer pin, and only a backend exit guarantees
                        release.

Summary count: 7 PROCSIG_RECOVERY_CONFLICT_* enum values,
covering DATABASE, TABLESPACE, LOCK, SNAPSHOT, LOGICALSLOT, BUFFERPIN,
and STARTUP_DEADLOCK.

Two-stage delivery summary:
  startup-side  (standby.c)  : Resolve* family -> SendProcSignal
  backend-side  (postgres.c) : HandleRecoveryConflictInterrupt sets bits,
                               ProcessRecoveryConflictInterrupt dispatches
                               at next CFI to ERROR/FATAL/release-pin.

Logging hook: log_recovery_conflict_waits=on routes long waits through
LogRecoveryConflict (standby.c:282) once deadlock_timeout has elapsed.
